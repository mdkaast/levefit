# Решения

- Этап 0: `@telegram-apps/sdk`, Lottie и модели БД добавляются на тех этапах, где они нужны.
- Этап 1: токены API подписываются HMAC (stdlib), без JWT-библиотеки; ключ — `APP_SECRET`.
- Этап 1: в `characters` добавлены `goal` (необязательна, пока не решён открытый вопрос), `workouts_per_week`, `equipment` — они нужны экрану создания персонажа, в таблице ТЗ их нет.
- Этап 1: `@telegram-apps/sdk` добавлен ради `retrieveRawInitData` (получение initData во фронтенде).
- Этап 1: список внешностей (`warrior`, `runner`, `sage`) — временный, пока не выбран стиль персонажа.
- Этап 2: общий справочник упражнений (24 шт.) вставляется миграцией 0002; `finish` пока только закрывает тренировку, XP добавится на этапе 3. Завершить тренировку без подходов нельзя.
- Этап 3: «сутки» и «неделя» считаются по UTC (понедельник — начало недели); пользовательские часовые пояса — позже.
- Этап 3: прогресс квестов и недельная цель считаются из журнала `xp_events` (засчитанные тренировки и подходы), поэтому лимиты нельзя обойти.
- Этап 3: недельная цель = `workouts_per_week` персонажа (по умолчанию 3). Тренировка сверх лимита 2 в сутки не даёт ни XP, ни очков характеристик, ни прогресса квестов.
- Этап 3: в `quests` добавлено поле `code` (тексты квестов — в локализации фронтенда), в `streaks` — `freeze_month` (для «одна заморозка в месяц»).
- Этап 3: набор квестов (2 дневных, 2 недельных) и очки характеристик (1 за подход, дисциплина +1 за тренировку и +5 за закрытую неделю) — стартовые значения в `game_rules/config.py`, требуют подтверждения.
- Этап 3: XP за вес (5) лежит в конфиге, начисляться будет на этапе 4.
- Этап 4: вес — `PUT /metrics/weight`, одна запись на дату (повтор заменяет значение). XP (5) только за запись на сегодняшнюю дату и один раз в сутки; ввод за прошлые даты (до года назад) XP не даёт, чтобы нельзя было накрутить.
- Этап 4: допустимый вес 20–500 кг; период графика по умолчанию — 90 дней; график рисуется SVG без библиотек.
- Этап 4: история тренировок перенесена с главной на экран «Прогресс», как в ТЗ.
- Этап 5: напоминания по схеме «бот опрашивает API»: бот раз в минуту вызывает `POST /internal/reminders/due` (заголовок `X-Internal-Key`, ключ `INTERNAL_API_KEY`; пусто — эндпоинт и рассылка отключены). Внутренние эндпоинты нельзя публиковать наружу через прокси.
- Этап 5: доставка «не более одного раза»: отметка `last_reminder_date` ставится при выдаче, поэтому сбой отправки не приводит к повторам. Напоминание можно отправить в течение 3 часов после заданного времени.
- Этап 5: напоминаем только пока недельная цель не достигнута и сегодня не было тренировки (дни отдыха не трогаем). Если в серии есть недели и оставшихся дней не больше, чем нужно тренировок, шлём «серия под угрозой».
- Этап 5: настройки в `users`: `reminders_enabled` (по умолчанию включено), `reminder_time` (19:00), `timezone` (IANA; пусто, пока клиент не сообщил, тогда UTC). Фронтенд сообщает пояс браузера при первом входе. Добавлена зависимость `tzdata` (zoneinfo на Windows и в slim-образах).
- Этап 5: заодно сделан экран «Профиль» и `DELETE /me` (в ТЗ они в экране профиля): удаление каскадом в БД, проверено тестом на данные всех таблиц.
- Этап 6: LLM — Claude через Anthropic API (`claude-opus-5-5` по умолчанию, меняется переменной `LLM_MODEL`; ключ — `ANTHROPIC_API_KEY`). Код зависит только от интерфейса `LLMProvider` (`app/ai/provider.py`), провайдер заменяем. Добавлена зависимость `anthropic` (клиент Messages API со структурированным выводом по схеме).
- Этап 6: ответ модели получаем через структурированный вывод (`messages.parse`) и дополнительно проверяем кодом (`app/ai/safety.py`): допустимые упражнения, диапазоны подходов и повторов, рост веса не более 10% (или 2,5 кг) за раз, без ссылок в тексте; при нарушении одна повторная попытка, затем 502 и ничего не сохраняется.
- Этап 6: безопасность ИИ: заметки пользователя передаются в JSON как данные (`user_notes`), системный промпт запрещает выполнять инструкции из них. При упоминании боли/травмы/симптомов (`health_flag`, поиск по словам) ответ обязан содержать совет обратиться к врачу или специалисту и не повышать вес и объём — иначе отклоняется. Советов по питанию и похудению промпт не допускает.
- Этап 6: рекомендации даём только по силовым упражнениям. План берётся из запроса (`plan`) или из прошлой рекомендации ИИ; без плана модель видит только факт. Одна рекомендация на тренировку (повтор возвращает сохранённую без нового вызова модели); лимит 10 вызовов ИИ в сутки на пользователя (429).
- Этап 6: в `ai_adjustments` добавлены `result` (полный проверенный ответ) и `model`; `POST /workouts/{id}/finish` принимает необязательные `notes` (иначе ввести заметки с экрана было бы негде).
- Этап 6: серверный откат при отказе модели (`fallbacks`, бета Anthropic) не включён: отказ или недоступность модели возвращают 503 без выдуманной рекомендации.
- Название приложения — Levefit.
- Дизайн: тёмная тема по референсам Tap Champion (Dribbble) и Luma (Behance) — стеклянные карточки, лаймовое свечение, розовый акцент для серии и наград, вертикальные градиентные шкалы характеристик, нижняя панель. Токены в `apps/web/src/styles.css`; шрифт системный (без сторонних запросов); арт персонажа — заглушка-аватар, пока не выбран стиль.
- Локальный запуск без Docker: API на SQLite (`apps/api/.env`, в git не попадает), web с прокси `/api` на API, `scripts/make_dev_init_data.py` печатает подписанный initData для проверок в обычном браузере.
- Онбординг по референсу «AI-Driven Onboarding for Fitness App» (Musemind): приветствие с неоновым «скелетом», шаги пол → возраст → рост и вес → цель → опыт → режим тренировок → целевые мышцы, полоски прогресса сверху, подсказки лаймовым текстом. Заменил форму создания персонажа.
- Дизайн сменён на чёрный фон и неоново-лаймовый акцент (референс онбординга); розовый оставлен только для серии и повышения уровня.
- В `characters` добавлены необязательные `gender`, `birth_year` (по возрасту при создании), `height_cm`, `experience`, `target_muscles`; стартовый вес записывается первой точкой графика без XP. Профиль попадает в снимок для ИИ как контекст. Внешность персонажа больше не спрашиваем (по умолчанию `warrior`), пока не выбран стиль арта.
- Туннель для проверки в Telegram: Cloudflare quick-туннель с этой сети работал нестабильно (ошибки 530/1033), переехали на SSH-туннель localhost.run (`ssh -R 80:127.0.0.1:5173 nokey@localhost.run`), адрес меняется при каждом запуске. Кнопка в старом сообщении `/start` хранит старый адрес — после смены туннеля нужно отправить `/start` заново.
- Бот: если Telegram доступен только через прокси, адрес берётся из `TELEGRAM_PROXY` или `HTTPS_PROXY` (нужна зависимость `aiohttp-socks`, её требует aiogram для любого прокси); при сетевых сбоях запуск polling повторяется.
- Локальный стенд для проверки в Telegram запускается `scripts\dev_up.ps1` (API, web, туннель, бот в фоне) и останавливается `scripts\dev_down.ps1`. `scripts\tunnel_supervisor.ps1` переподнимает SSH-туннель localhost.run и при каждой смене (бесплатные адреса меняются) вызывает `scripts\apply_tunnel_url.ps1`: пишет `WEBAPP_URL`, перезапускает бота и выставляет кнопку меню. Кнопки в старых сообщениях `/start` после смены адреса нерабочие — открывать через кнопку меню.
- Корректировки к ТЗ (`docs/tz-corrections.md`), реализация. Решения владельца: тёмный неоновый дизайн остаётся (строгим делаем тон текстов); расписания тренировочных дней нет; XP за запись веса (5) остаётся, хотя раздел 6 корректировок запрещает награды «за цифры на весах» (награда за факт записи, не за значение; решение владельца); ежедневные задания выдают правила на сервере, ИИ работает только после тренировки.
- Терминология: «квест» заменён на «задание» (таблицы `tasks`, `user_tasks`, `GET /tasks`, источник XP `task`; миграция 0008 сохраняет данные). У задания два поля: `period` (daily/weekly) и `kind` (main/minor/recovery).
- Тип дня без расписания: пока недельная цель не выполнена на начало дня — выдаются основное и малое задания; когда цель выполнена — день отдыха (восстановление и малое). Состав фиксируется на начало дня. Пропущенный день ничего не списывает: заданий «на отработку» нет, XP, уровень и характеристики не снижаются. Замена пропущенного дня заданием восстановления из раздела 3 не делалась (без расписания «пропуск» не определён).
- Задание восстановления подтверждается вручную (`POST /tasks/{id}/complete`, +10 XP, один раз в сутки); остальные закрываются автоматически по журналу, в том числе при просмотре `/tasks` (самовосстановление).
- Ранги по уровню (границы 1/10/20/30/40/50 из конфига, чистая функция `rank_for_level`), очки уровня: +1 за уровень, пока только копятся. Достижения: 8 штук, считаются по журналу, веса и размеров тела в условиях нет.
- Режим паузы (`users.mode`, `paused_at`): только восстановление, недельных заданий нет, серия заморожена и при возврате сдвигается на длину паузы, напоминания не отправляются.
- Напоминания: тексты бота вынесены в `bot/texts.py` в деловом тоне по образцам; лимит в сутки — `MAX_REMINDERS_PER_DAY` в конфиге.
- План следующей тренировки: `GET /plan` отдаёт последнюю рекомендацию ИИ, экран тренировки подставляет цель по нажатию.


## ИИ-тренер: обучение вручную и по оценкам (25.10.2026)

OpenClaw не подключаем: это личный ассистент с одной границей доверия, не рассчитан на многих пользователей и данные о здоровье, плюс не помещается в 1 ГБ ОЗУ сервера. Обучение сделано в бэкенде: правила владельца (`coach_rules`, `/admin/coach/rules`), оценки пользователей (`POST /workouts/{id}/adjust/feedback`: fits, too_hard, too_easy), предложения правил от ИИ (`POST /admin/coach/learn`, статус proposed). В запрос к модели попадают только одобренные правила; проверки `safety.py` действуют всегда. Админка закрыта ключом `ADMIN_API_KEY` и в Caddy снаружи отдаёт 404.

## Админ-панель (25.10.2026)

Вкладка «Админ» в приложении видна только Telegram ID из `ADMIN_TELEGRAM_IDS` (проверка на сервере по подписанному токену; ключ `ADMIN_API_KEY` тоже подходит для запросов с сервера). Вкладки: аналитика (`/admin/stats`), ИИ (`/admin/ai/recent`, оценки), обучение (правила и предложения ИИ), изменения (`/admin/requests`: форма собирает готовый текст запроса для Claude Code, его можно копировать; сам сайт Claude Code не запускает). Ограничение на `/api/admin/*` в Caddy снято: защита только проверкой админа. В аналитике нет персональных данных пользователей.

## Фаза 1: движок решений (26.10.2026)

- Числа нагрузки считает `app/engine`, ИИ-тренер только объясняет (`docs/engine.md`). При недоступности ИИ или двух нарушениях текста решение сохраняется с шаблонным объяснением, поэтому `/adjust` больше не отвечает 503 и 429.
- Лимит объяснений ИИ в сутки (10) остаётся: при превышении объяснение берётся из шаблона.
- Проверка объяснения: любой названный вес в кг должен быть из решения движка; это даёт сверку «что сказал тренер» и «что решил движок».
- Округление снижений идёт к ближайшему шагу инвентаря (72 кг → 72,5), повышения всегда на целый шаг.

## Фаза 1: цикл тренировки (26.10.2026)

- Оценка упражнения даёт движку сигнал, а не число: «Тяжело» запрещает повышение веса при выполненных повторах, «Легко» разрешает повышение при запасе меньше цели. Сама по себе оценка вес не снижает.
- Боль, отмеченная до тренировки или в оценке упражнения, считается жалобой на боль так же, как слово в заметках.
- Пропуск не отнимает XP и серию. Он нужен движку как сигнал (два за 10 дней) и для главного экрана; повторный пропуск в тот же день заменяет первый.
- Ручная правка веса в итоге сохраняется отдельно от решения движка (`overrides`): журнал хранит оба значения и причину.
- Тренировку можно начать только при связи (нужен её номер), подходы и оценки после этого пишутся через очередь; завершить тренировку можно, когда очередь пуста.
