# Решения

- Этап 0: `@telegram-apps/sdk`, Lottie и модели БД добавляются на тех этапах, где они нужны.
- Этап 1: токены API подписываются HMAC (stdlib), без JWT-библиотеки; ключ — `APP_SECRET`.
- Этап 1: в `characters` добавлены `goal` (необязательна, пока не решён открытый вопрос), `workouts_per_week`, `equipment` — они нужны экрану создания персонажа, в таблице ТЗ их нет.
- Этап 1: `@telegram-apps/sdk` добавлен ради `retrieveRawInitData` (получение initData во фронтенде).
- Этап 1: список внешностей (`warrior`, `runner`, `sage`) — временный, пока не выбран стиль персонажа.
- Этап 2: общий справочник упражнений (24 шт.) вставляется миграцией 0002; `finish` пока только закрывает тренировку, XP добавится на этапе 3. Завершить тренировку без подходов нельзя.
- Этап 3: «сутки» и «неделя» считаются по UTC (понедельник — начало недели); пользовательские часовые пояса — позже.
- Этап 3: прогресс квестов и недельная цель считаются из журнала `xp_events` (засчитанные тренировки и подходы), поэтому лимиты нельзя обойти.
- Этап 3: недельная цель = `workouts_per_week` персонажа (по умолчанию 3). Тренировка сверх лимита 2 в сутки не даёт ни XP, ни очков характеристик, ни прогресса квестов.
- Этап 3: в `quests` добавлено поле `code` (тексты квестов — в локализации фронтенда), в `streaks` — `freeze_month` (для «одна заморозка в месяц»).
- Этап 3: набор квестов (2 дневных, 2 недельных) и очки характеристик (1 за подход, дисциплина +1 за тренировку и +5 за закрытую неделю) — стартовые значения в `game_rules/config.py`, требуют подтверждения.
- Этап 3: XP за вес (5) лежит в конфиге, начисляться будет на этапе 4.
- Этап 4: вес — `PUT /metrics/weight`, одна запись на дату (повтор заменяет значение). XP (5) только за запись на сегодняшнюю дату и один раз в сутки; ввод за прошлые даты (до года назад) XP не даёт, чтобы нельзя было накрутить.
- Этап 4: допустимый вес 20–500 кг; период графика по умолчанию — 90 дней; график рисуется SVG без библиотек.
- Этап 4: история тренировок перенесена с главной на экран «Прогресс», как в ТЗ.
- Этап 5: напоминания по схеме «бот опрашивает API»: бот раз в минуту вызывает `POST /internal/reminders/due` (заголовок `X-Internal-Key`, ключ `INTERNAL_API_KEY`; пусто — эндпоинт и рассылка отключены). Внутренние эндпоинты нельзя публиковать наружу через прокси.
- Этап 5: доставка «не более одного раза»: отметка `last_reminder_date` ставится при выдаче, поэтому сбой отправки не приводит к повторам. Напоминание можно отправить в течение 3 часов после заданного времени.
- Этап 5: напоминаем только пока недельная цель не достигнута и сегодня не было тренировки (дни отдыха не трогаем). Если в серии есть недели и оставшихся дней не больше, чем нужно тренировок, шлём «серия под угрозой».
- Этап 5: настройки в `users`: `reminders_enabled` (по умолчанию включено), `reminder_time` (19:00), `timezone` (IANA; пусто, пока клиент не сообщил, тогда UTC). Фронтенд сообщает пояс браузера при первом входе. Добавлена зависимость `tzdata` (zoneinfo на Windows и в slim-образах).
- Этап 5: заодно сделан экран «Профиль» и `DELETE /me` (в ТЗ они в экране профиля): удаление каскадом в БД, проверено тестом на данные всех таблиц.
- Этап 6: LLM — Claude через Anthropic API (`claude-opus-5-5` по умолчанию, меняется переменной `LLM_MODEL`; ключ — `ANTHROPIC_API_KEY`). Код зависит только от интерфейса `LLMProvider` (`app/ai/provider.py`), провайдер заменяем. Добавлена зависимость `anthropic` (клиент Messages API со структурированным выводом по схеме).
- Этап 6: ответ модели получаем через структурированный вывод (`messages.parse`) и дополнительно проверяем кодом (`app/ai/safety.py`): допустимые упражнения, диапазоны подходов и повторов, рост веса не более 10% (или 2,5 кг) за раз, без ссылок в тексте; при нарушении одна повторная попытка, затем 502 и ничего не сохраняется.
- Этап 6: безопасность ИИ: заметки пользователя передаются в JSON как данные (`user_notes`), системный промпт запрещает выполнять инструкции из них. При упоминании боли/травмы/симптомов (`health_flag`, поиск по словам) ответ обязан содержать совет обратиться к врачу или специалисту и не повышать вес и объём — иначе отклоняется. Советов по питанию и похудению промпт не допускает.
- Этап 6: рекомендации даём только по силовым упражнениям. План берётся из запроса (`plan`) или из прошлой рекомендации ИИ; без плана модель видит только факт. Одна рекомендация на тренировку (повтор возвращает сохранённую без нового вызова модели); лимит 10 вызовов ИИ в сутки на пользователя (429).
- Этап 6: в `ai_adjustments` добавлены `result` (полный проверенный ответ) и `model`; `POST /workouts/{id}/finish` принимает необязательные `notes` (иначе ввести заметки с экрана было бы негде).
- Этап 6: серверный откат при отказе модели (`fallbacks`, бета Anthropic) не включён: отказ или недоступность модели возвращают 503 без выдуманной рекомендации.
